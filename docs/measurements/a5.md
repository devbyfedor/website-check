## Diagnosis: what a start costs

One more deploy (20:19), then `/lab/cost` (lab only): each operation of a start alone, four times, interleaved (24 requests, 22 with their event).

- Nothing at all, first request of a fresh instance: 0 ms (0, 0, 0, 0). A fresh instance of the small bundle costs nothing measurable.
- One D1 read: 2 ms on the first request of the second fresh instance, then 0, 0, 0.
- Six D1 reads in a row: 4, 3, 2, 2 ms.
- The SSRF guard on example.com (two DNS-over-HTTPS queries and the address rules): 2, 1, 1, 2 ms.
- One request to the queue object: 0, 0, 0 ms. The visitor hash (HMAC): 0, 0, 0 ms.

A start makes about nine round trips in the Worker: six to D1 (cache lookup, the salt of the day, the rate-limit slot, two for the new scan; three of them write batches), two DNS-over-HTTPS queries and one to the queue object. Measured alone these add up to about 5 to 6 ms; the starts measured 2 to 19 ms, with the same code on every round (round 2 ran 7, 3, 2, 3 ms). So the cost is the start's own work plus a noise of several milliseconds, not the size of the bundle or a fresh instance.
